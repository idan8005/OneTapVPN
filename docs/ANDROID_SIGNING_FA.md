# امضای پایدار نسخه‌های Android در Raahat VPN

برای اینکه نسخه‌های بعدی برنامه بدون خطای «برنامه نصب نشد / امضای متفاوت است» روی نسخهٔ قبلی نصب شوند، همهٔ APKهای آینده باید با **یک کلید خصوصی ثابت** امضا شوند.

## ساخت کلید با دوبار کلیک

1. در ویندوز، فایل `tools/prepare-android-signing.cmd` را از مخزن دریافت کنید.
2. روی آن دوبار کلیک کنید. اسکریپت، ابزار `keytool` را از Java نصب‌شده (معمولاً همراه Android Studio) پیدا می‌کند.
3. دو فایل در پوشهٔ Documents\RaahatVPN-Signing ساخته می‌شود:
   - `raahat-release.p12`: کلید خصوصی اصلی؛ حتماً از آن نسخهٔ پشتیبان امن نگه دارید.
   - `GitHub-Actions-Secrets.txt`: مقادیر لازم برای تنظیم GitHub.

اگر فایل‌ها از قبل وجود داشته باشند، اسکریپت آن‌ها را بازنویسی نمی‌کند.

## ثبت چهار مقدار در GitHub

در مخزن [idan8005/OneTapVPN](https://github.com/idan8005/OneTapVPN) وارد مسیر زیر شوید:

**Settings → Secrets and variables → Actions → New repository secret**

چهار Secret با نام‌های دقیق زیر بسازید و مقدار متناظر را از فایل `GitHub-Actions-Secrets.txt` قرار دهید:

- `RAAHAT_ANDROID_KEYSTORE_BASE64`
- `RAAHAT_ANDROID_STORE_PASSWORD`
- `RAAHAT_ANDROID_KEY_ALIAS`
- `RAAHAT_ANDROID_KEY_PASSWORD`

مقادیر این چهار Secret خصوصی هستند. آن‌ها را در چت، Issue، فایل عمومی یا commit قرار ندهید.

## رفتار CI پس از تنظیم

- APKهای Debug و Release با همان کلید ثابت امضا می‌شوند.
- CI امضای تمام APKهای Release را با `apksigner` بررسی می‌کند.
- تا زمانی که هر چهار Secret ثبت نشده باشند، ساخت Debug و تست‌ها ادامه پیدا می‌کنند؛ ساخت Release امضاشده عمداً اجرا نمی‌شود.
- فایل کلید در هیچ‌کدام از commitهای مخزن قرار نمی‌گیرد؛ فقط در محیط موقت GitHub Actions استفاده می‌شود.

## هشدار مهم دربارهٔ نسخه‌های قدیمی

APKهای Debug قبلی با کلیدهای موقت runner ساخته شده‌اند و آن کلیدها در مخزن ذخیره نشده‌اند. بنابراین نصب نسخه‌ای که با کلید پایدار جدید امضا شده روی بعضی از نصب‌های قدیمی ممکن است به‌دلیل تفاوت امضا رد شود. **برنامهٔ قدیمی را حذف نکنید** تا پیش از آن، مسیر پشتیبان‌گیری و انتقال امن اطلاعات بررسی شود.

از دست دادن فایل `raahat-release.p12` به معنی از دست دادن امکان انتشار به‌روزرسانی سازگار با همین امضا است. آن را در یک محل امن و جداگانه پشتیبان‌گیری کنید.

این تنظیم فقط زنجیرهٔ امضای Android را پایدار می‌کند؛ به‌تنهایی به معنی تکمیل تونل Windows/iOS یا آماده بودن محصول برای انتشار عمومی نیست.
