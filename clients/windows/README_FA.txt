راهنمای اجرای راحت وی‌پی‌ان در ویندوز

1. فایل ZIP را به‌طور کامل در یک پوشه استخراج کنید.
2. فایل شروع-راحت-وی-پی-ان.cmd یا RaahatVPN.exe را اجرا کنید.
3. در پیام Windows UAC گزینه Yes را بزنید. برای ساخت TUN و مدیریت موقت فایروال، برنامه به مجوز مدیر نیاز دارد.
4. برای اتصال خودکار، کادر لینک سرور را خالی بگذارید. برنامه فهرست عمومی BLACK_FULL را دریافت و فقط لینک‌های سازگار VLESS + REALITY با انتقال TCP را انتخاب می‌کند؛ میزبان‌های متفاوت در اولویت‌اند. یا حداکثر پنج لینک دستی وارد کنید.
5. دکمه اتصال را بزنید. برنامه سرورها را به‌ترتیب امتحان می‌کند و فقط خروجی IPv4 تأییدشده را می‌پذیرد.
6. هنگام اتصال، Kill Switch ویندوز فعال است. برای قطع VPN از دکمه قطع اتصال استفاده کنید تا تنظیمات قبلی فایروال بازیابی شوند.

رفتار Kill Switch:
- مقصد سرور قبل از قفل فایروال به IP عمومی IPv4 تبدیل و در تنظیمات sing-box ثابت می‌شود؛ نام SNI اصلی برای TLS حفظ می‌شود.
- فقط خروجی از رابط TUN و اتصال موتور sing-box به IP/پورت سرور اجازه دارد. دسترسی به IPهای خصوصی LAN نیز برای ارتباط محلی مجاز می‌ماند.
- قوانین خروجی Allow قبلی ویندوز موقتاً ذخیره و غیرفعال می‌شوند تا برنامه‌های دیگر نتوانند از مسیر فیزیکی عبور کنند. هنگام قطع عادی، وضعیت قبلی آن‌ها بازگردانده می‌شود.
- یک وظیفهٔ بازیابی با حساب SYSTEM هر دقیقه قفل فایروال را بررسی می‌کند و Allowهای تازه را هم موقتاً غیرفعال می‌سازد.
- اگر برنامه ناگهانی بسته شود یا ویندوز restart شود، اینترنت خروجی در حالت مسدود می‌ماند. با اجرای دوبارهٔ راحت‌وی‌پی‌ان، تنظیمات قبلی بازیابی می‌شوند. تا بازکردن دوبارهٔ برنامه ممکن است اینترنت عادی در دسترس نباشد؛ این رفتار برای جلوگیری از نشت عمدی است.
- اگر سیاست سازمانی یا فایروال دیگری اجازهٔ کنترل محلی ندهد، برنامه از فعال‌سازی Kill Switch و شروع اتصال خودداری می‌کند.
- اگر بازیابی فایروال با خطا روبه‌رو شود، اینترنت تا زمان تکمیل بازیابی مسدود می‌ماند؛ برنامه اتصال جدید را تا رفع وضعیت اجازه نمی‌دهد.

منبع فهرست عمومی:
- پروژه FLAT447/v2ray-lists، فایل BLACK_FULL.txt
- دریافت از CDN عمومی و دو آدرس جایگزین GitHub
- این فهرست متعلق به Raahat نیست؛ وضعیت سرورها ممکن است هر لحظه تغییر کند.

مهم:
- این نسخه فقط VLESS + REALITY روی TCP را پشتیبانی می‌کند. OpenVPN، WebSocket، gRPC، XHTTP و پروتکل‌های دیگر پذیرفته نمی‌شوند.
- لینک‌های فهرست عمومی فقط کاندید اولیه‌اند؛ اتصال هر سرور باید از شبکهٔ خود شما و با عبور واقعی ترافیک IPv4 تأیید شود.
- انتخاب برنامه‌ها (Split Tunneling) هنوز آماده نیست.
- تست مستقل نشت DNS و IPv6، جابه‌جایی Wi-Fi به Ethernet و قطع ناگهانی تونل هنوز روی دستگاه واقعی لازم است.
- سرورهای عمومی متعلق به اشخاص ناشناس ممکن است ترافیک یا فراداده را ثبت کنند. برای اطلاعات بانکی یا حساس استفاده نکن.
- برای تأیید خروجی IPv4، یک درخواست HTTPS به api.ipify.org ارسال می‌شود؛ این سرویس بیرونی IP خروجی را می‌بیند.
