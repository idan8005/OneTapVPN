# راحت وی‌پی‌ان | Raahat VPN

راحت وی‌پی‌ان با مدل **Hybrid** توسعه می‌یابد: اتصال رایگان به سرورهای عمومی داوطلبانه و اتصال ویژه به سرورهایی که خود سرویس مدیریت و پایش می‌کند. هدف نهایی، کلاینت‌های Android، Windows و iOS است. **WireGuard در این پروژه استفاده نمی‌شود.**

## وضعیت فعلی

- کلاینت فعلی Android با Kotlin در `app/` قرار دارد.
- موتورهای Android شامل OpenVPN برای برخی سرورهای عمومی و sing-box برای پروفایل‌های VLESS + REALITY هستند.
- کشف سرور، رتبه‌بندی سلامت، Full Tunnel، انتخاب برنامه‌ها و به‌روزرسانی APK در کد Android وجود دارد؛ اتصال واقعی باید روی گوشی و شبکهٔ موردنظر تست شود.
- سرویس مرکزی Hybrid در `backend/` اضافه شده؛ هنوز به Android متصل یا روی میزبان عمومی مستقر نشده است.
- Windows، iOS، پرداخت، پنل گرافیکی و سرورهای Premium عملیاتی هنوز تکمیل نشده‌اند.

جزئیات در [نقشه راه Hybrid](HYBRID_ROADMAP_FA.md) آمده است.

## سرورهای رایگان

منابع عمومی فقط فهرست نامزد هستند و توسط راحت وی‌پی‌ان اداره نمی‌شوند. اپراتور سرور داوطلبانه ممکن است ترافیک عبوری را ببیند یا ثبت کند؛ برای بانکداری، گذرواژه و اطلاعات محرمانه از سرور ناشناس استفاده نکنید. سرعت اعلام‌شده، سرعت واقعی یا دسترسی دائمی را تضمین نمی‌کند.

## اتصال حساب Android به سرویس Hybrid

در برنامه دکمهٔ «حساب و اشتراک ویژه» کد دسترسی را دریافت می‌کند و آن را با کلید غیرقابل‌استخراج Android Keystore رمزنگاری می‌کند. فهرست سرورهای ویژه جدا از فهرست عمومی ذخیره می‌شود و فقط پروفایل‌های سازگار VLESS + REALITY از HTTPS پذیرفته می‌شوند؛ اطلاعات Host و Port با داخل پروفایل تطبیق داده می‌شوند. توکن در log نوشته نمی‌شود و انتقال آن به نشانی غیر HTTPS رد می‌شود.

برای تنظیم نشانی API هنگام ساخت Android، متغیر محیطی عمومی `RAAHAT_API_BASE_URL` را به دامنه HTTPS سرویس مرکزی تنظیم کنید. این مقدار محرمانه نیست و توکن یا کلید مدیر نباید داخل BuildConfig یا APK قرار بگیرد. تا وقتی نشانی سرویس واقعی تنظیم و backend روی HTTPS مستقر نشده، همگام‌سازی ویژه در برنامه غیرفعال می‌ماند و مسیر رایگان مستقل کار می‌کند.

کلاینت Android فعلاً فقط ورودی‌های `vless-reality` را می‌پذیرد؛ ورودی `openvpn` در کاتالوگ سمت سرور تا زمان ساخت adapter اختصاصی Android رد می‌شود. این محدودیت به‌صورت عمدی است تا برنامه کانفیگ را با موتور ناسازگار اجرا نکند.

## سرویس مرکزی Hybrid

سرویس Go در `backend/` امکانات پایه دارد:

- `GET /healthz` برای سلامت سرویس
- `GET /api/v1/catalog` برای کاتالوگ کاربران دارای توکن
- `PUT /admin/v1/servers` برای مدیریت فهرست Premium
- `POST /admin/v1/tokens` برای صدور توکن زمان‌دار
- HMAC-SHA256 برای امضای توکن و AES-256-GCM برای رمزنگاری کاتالوگ در دیسک

برای اجرا و API به [راهنمای سرویس مرکزی](backend/README_FA.md) مراجعه کنید. این API هنوز به پرداخت، سامانه ثبت‌نام، کلاینت‌ها یا سرور واقعی متصل نیست.

## ساخت و آزمون Android

پیش‌نیاز: JDK 17، Android SDK Platform 34 و Gradle 8.7.

```bash
gradle --no-daemon :app:lintDebug
gradle --no-daemon :app:testDebugUnitTest
gradle --no-daemon :app:assembleDebug
```

## آزمون سرویس مرکزی

پیش‌نیاز: Go 1.23 یا جدیدتر.

```bash
cd backend
go test -race ./...
go vet ./...
go build ./...
```

## امضا و به‌روزرسانی Android

نسخه‌های بعدی باید با همان کلید امضای پایدار ساخته شوند. کلیدها فقط در GitHub Secrets یا secret manager میزبان نگهداری شوند؛ هرگز آن‌ها را در سورس یا APK قرار ندهید. نصب نهایی نسخه جدید در Android به تأیید نصب‌کننده سیستم‌عامل نیاز دارد.
