# راحت وی‌پی‌ان (Raahat VPN)

راحت وی‌پی‌ان یک محصول چندسکویی با مدل Hybrid است: سرورهای عمومی رایگان در کنار زیرساخت اختصاصی Premium.

**پلتفرم‌ها:** Android، Windows و iOS  
**موتور Android و Windows:** sing-box 1.14.4  
**WireGuard:** استفاده نمی‌شود.

## ساختار پروژه
- backend/ — API مرکزی، کاتالوگ سرورها و آداپترهای منابع عمومی با Go
- clients/android/ — کلاینت Kotlin و Jetpack Compose با Android VpnService
- clients/windows/ — کلاینت WPF با موتور TUN واقعی sing-box برای VLESS + REALITY روی TCP
- clients/windows-verification/ — تست parser و بررسی واقعی پیکربندی تولیدشده با sing-box
- clients/ios/ — برنامه SwiftUI و افزونه Packet Tunnel متصل به چارچوب رسمی sing-box؛ امضای Apple و آزمایش روی iPhone باقی است
- contracts/ — قرارداد API
- docs/ — معماری، راهنمای فارسی پلتفرم‌ها و وضعیت واقعی پیاده‌سازی

## Android — سرورهای رایگان
با انتخاب «اتصال خودکار رایگان»، برنامه مستقیماً فهرست CSV رسمی VPN Gate را از HTTPS دریافت می‌کند. سپس:
- پروفایل‌های OpenVPN را از داخل برنامه بررسی می‌کند و فقط آدرس و میزبان منطبق با رکورد منبع را می‌پذیرد.
- پروفایل‌های TCP را با آزمایش پورت TCP فیلتر می‌کند.
- پروفایل‌های UDP را جدا نگه می‌دارد؛ UDP با تست TCP قابل سنجش نیست و باید با دست‌دهی OpenVPN آزمایش شود.
- سرورهای پیدا‌شده را با پینگ منبع مرتب می‌کند و سریع‌ترین گزینه‌ها را برای اتصال امتحان می‌کند.
- اگر تونل یا آزمایش مستقل HTTPS شکست بخورد، حداکثر سه کاندید برتر را به‌ترتیب امتحان می‌کند.
- سروری که اتصال واقعی‌اش شکست بخورد، با شناسهٔ غیرمحرمانه تا ۱۵ دقیقه از فهرست و انتخاب خودکار کنار گذاشته می‌شود؛ پس از پایان زمان دوباره قابل بررسی است.

فایل پروفایل و اطلاعات ورود فقط در حافظه برنامه استفاده می‌شوند؛ در API فهرست عمومی یا لاگ‌ها قرار نمی‌گیرند. پیکربندی نهایی قبل از شروع تونل با `Libbox.checkConfig` بررسی می‌شود. هنگام فعال بودن Full Tunnel، برنامه در لایهٔ Android مسیر پیش‌فرض IPv4 و IPv6 را به رابط VPN اضافه می‌کند، اگر موتور فقط مسیرهای جزئی ارائه دهد. در Android 13 به بالا از iteratorهای prefix و در نسخه‌های قدیمی‌تر از route-range استفاده می‌شود تا مقصدهای پوشش‌داده‌نشده از شبکهٔ فیزیکی گوشی عبور نکنند. در پروفایل OpenVPN، گزینهٔ `block_ipv6` ترافیک IPv6 را داخل موتور مسدود می‌کند؛ در VLESS مسیر IPv6 به خروجی پروکسی تحویل می‌شود. DNS و خروجی IPv4 با درخواست‌های HTTPS آزمایش می‌شوند و فقط در صورت موفقیت هر دو، وضعیت «متصل» اعلام می‌شود. پاسخ IPv6 نیز جداگانه بررسی می‌شود، اما تست نشت مستقل روی دستگاه و هنگام قطع تونل هنوز انجام نشده است.

**محدودیت امنیتی:** سرورهای VPN Gate را داوطلبان مستقل اداره می‌کنند و ممکن است ترافیک را ثبت کنند؛ برای اطلاعات حساس مناسب نیستند. برای TCP، پاسخ پورت فقط پیش‌سنجی است. برای UDP، معیار نهایی دست‌دهی واقعی و عبور ترافیک از تونل است.

## Windows — اولین نسخهٔ دارای تونل واقعی
کلاینت Windows اکنون به موتور رسمی sing-box 1.14.4 وصل است و از لینک VLESS + REALITY با TCP پشتیبانی می‌کند:
- لینک قبل از اجرا اعتبارسنجی می‌شود؛ لینک‌های نامعتبر یا نوع انتقال پشتیبانی‌نشده رد می‌شوند.
- برنامه یک رابط TUN با Full Tunnel، strict routing و DNS-over-HTTPS تنظیم می‌کند. شبکه‌های خصوصی و محلی برای دسترسی LAN مستثنا هستند.
- پیکربندی تولیدشده پیش از اتصال با خود موتور sing-box بررسی می‌شود.
- باینری رسمی Windows x64 در CI از مخزن upstream دریافت و با SHA-256 ثابت اعتبارسنجی می‌شود.
- برنامه برای ایجاد TUN و تغییر مسیرهای شبکه به تأیید Administrator از طریق UAC نیاز دارد.
- فایل پیکربندی جلسه موقت و delete-on-close است و خروجی موتور در لاگ‌های Raahat ذخیره نمی‌شود.
- برنامه پردازش موتور را با Windows Job Object کنترل می‌کند تا هنگام بسته شدن برنامه، پردازش تونل نیز متوقف شود.
- تأیید خروجی IPv4 با مقایسهٔ IP عمومی قبل و بعد از اتصال از طریق HTTPS انجام می‌شود؛ این آزمایش به معنی تأیید نشت DNS/IPv6 نیست.

**محدودیت‌های Windows این مرحله:** سرور‌یابی خودکار، واردکردن OpenVPN، split tunneling برنامه‌ای، Kill Switch ویندوز، Always-on، اتصال مجدد خودکار و به‌روزرسانی درون‌برنامه‌ای هنوز تکمیل نشده‌اند. پیش از استفادهٔ حساس، تست واقعی DNS، IPv6 و قطع اجباری موتور لازم است. راهنمای کامل در [docs/WINDOWS_CLIENT_FA.md](docs/WINDOWS_CLIENT_FA.md) قرار دارد.

## Backend
پیش‌نیاز: Go نسخه 1.23 یا جدیدتر.

از پوشه backend اجرا کنید:

    go test -race ./...
    go run ./cmd/api

API به‌صورت پیش‌فرض روی 127.0.0.1:8080 اجرا می‌شود:
- GET /healthz
- GET /api/v1/health
- GET /api/v1/servers
- GET /api/v1/servers?tier=free
- GET /api/v1/servers?tier=premium

کاتالوگ اولیه عمداً خالی است. برای بارگذاری سرورهای مدیریت‌شده، مقدار `RAAHAT_CATALOG_FILE` را به فایل JSON معتبر تنظیم کنید.

آداپتر Backend برای VPN Gate مستقل از اسکن مستقیم Android است و در حال حاضر فقط پروفایل‌های TCP را وارد کاتالوگ سلامت‌سنجی می‌کند. برای فعال کردن به‌روزرسانی کاتالوگ، مقدار `RAAHAT_VPNGATE_ENABLED=true` را تنظیم کنید. منبع هر ۲۰ دقیقه به‌روزرسانی می‌شود و خرابی منبع باعث پاک‌شدن آخرین کاتالوگ معتبر نمی‌شود.

برای استقرار عمومی، TLS باید روی سرویس یا پراکسی معتمد جلوی آن فعال باشد. سرویس HTTP بدون TLS را مستقیماً در اینترنت منتشر نکنید.

## امضای پایدار Android
ساخت CI از یک کلید خصوصی ثابت برای امضای Debug و Release پشتیبانی می‌کند. کلید فقط در GitHub Actions Secrets نگهداری می‌شود و وارد مخزن عمومی نمی‌شود. برای ساخت یک‌بارهٔ کلید و ثبت Secretها، راهنمای [docs/ANDROID_SIGNING_FA.md](docs/ANDROID_SIGNING_FA.md) و فایل اجرایی [tools/prepare-android-signing.cmd](tools/prepare-android-signing.cmd) را ببینید. تا قبل از ثبت هر چهار Secret، ساخت Release امضاشده عمداً رد می‌شود و CI همچنان Debug و تست‌ها را اجرا می‌کند.

**هشدار مهاجرت:** APKهای Debug پیش از فعال‌سازی این کلید با کلیدهای موقت CI ساخته شده‌اند. نصب نسخهٔ دارای امضای پایدار روی بعضی از آن نصب‌ها ممکن است رد شود. پیش از حذف نسخهٔ قبلی باید مسیر انتقال امن اطلاعات آماده باشد. فایل کلید خصوصی را گم نکنید و در مخزن یا چت منتشر نکنید.

## iOS — اتصال اولیه به موتور VPN
هستهٔ Swift لینک‌های VLESS + REALITY روی TCP را اعتبارسنجی می‌کند و پیکربندی sing-box برای Full Tunnel و DNS-over-HTTPS می‌سازد. برنامه با `NETunnelProviderManager` پروفایل VPN سیستم Apple را ایجاد می‌کند و پیکربندی را به Packet Tunnel می‌فرستد. افزونه با `LibboxCheckConfig` آن را بررسی می‌کند، موتور sing-box را راه می‌اندازد و TUN/DNS/routeها را به `NEPacketTunnelNetworkSettings` متصل می‌کند. فایل اتصال در App Group محافظت‌شده ذخیره می‌شود و هنگام قطع دستی کاربر پاک می‌شود. وضعیت خروجی IPv4 نیز با مقایسهٔ IP قبل و بعد بررسی می‌شود.

Framework رسمی Libbox نسخهٔ 1.14.4 برای iPhone و شبیه‌ساز توسط CI ساخته شده است. ساخت نهایی Xcode با Framework متصل هنوز در حال تأیید است؛ بنابراین این milestone را نسخهٔ iOS قابل نصب یا آمادهٔ استفاده اعلام نمی‌کنیم.

**محدودیت مهم:** هنوز امضای Apple Developer، provisioning، ثبت App Group و مجوز Network Extension لازم است. آزمایش روی iPhone واقعی، نشت DNS/IPv6، قطع اجباری تونل و اتصال مجدد پس از تغییر شبکه انجام نشده است. نسخهٔ CI بدون امضای Apple قابل نصب روی iPhone نیست. جزئیات در [docs/STATUS.md](docs/STATUS.md) آمده است.

## وضعیت انتشار
نسخهٔ Android در شاخهٔ توسعه `0.3.6-dev` است و Windows اولین milestone عملیاتی خود را در `0.2.0-dev` دارد. CI ساخت، تست واحد و اعتبارسنجی پیکربندی را اجرا می‌کند؛ این موارد جای آزمایش اتصال واقعی روی چند دستگاه و شبکه را نمی‌گیرند. Premium، پرداخت، سرورهای مدیریت‌شده و به‌روزرسانی امضاشدهٔ درون‌برنامه‌ای هنوز تکمیل نشده‌اند. iOS به امضا، provisioning و آزمایش دستگاه واقعی نیاز دارد.

در Android، پشتیبانی Always-on فعال است و پیکربندی آخرین اتصال با Android Keystore و AES-GCM رمزگذاری می‌شود. کاربر باید Kill Switch را در تنظیمات VPN خود Android فعال کند؛ برنامه آن را خودکار روشن نمی‌کند. در Android 10 به بعد، صفحهٔ اصلی وضعیت واقعی Always-on و Lockdown را از Android می‌خواند.

این محصول هنوز نسخهٔ توسعه است و تا عبور از آزمون‌های دستگاه واقعی و بازبینی امنیتی مستقل، نباید به‌عنوان VPN آمادهٔ انتشار عمومی معرفی شود.
